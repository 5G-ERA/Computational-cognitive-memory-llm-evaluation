\title{\vspace{-1cm}\textcolor{navy}{\Huge Medical Assumption Memory Benchmark v0.5}\\\Large Semantic robustness, controls, and system-improvement protocol}\date{13 August 2026}\begin{document}\sloppy\emergencystretch=2em\maketitle
\noindent\colorbox{pale}{\parbox{.96\linewidth}{\textbf{Status.} Development package for testing whether verified relational memory improves recovery of deterministic reactions across unseen language renderings. Correctness is computational, not medical.}}
\section{Objective}v0.5 extends the API-ready v0.4.2 system with balanced five-class canonical states, three independent render families, relational successor evidence, development-only mechanism controls, and a run-completion gate. The primary contrasts remain $B1-B0$ and $B1-M0$.
\section{Data}The package contains 200 canonical contexts, 40 per reaction. Each is rendered in structured, chronological, and concise language, producing 600 rendered contexts and 1,800 B0/M0/B1 calls. Forty canonical contexts form development and 160 form reserved evaluation, with all renderings kept in the same split.
\section{Memory construction}A prospective assumption and expected consequence are frozen before follow-up. Source-level observations are resolved into a relational memory containing the observed relation, constitutive and competing provenance, scope, limitations, and optional successor relation. Internal labels such as successor VERIFIED are not exposed; the memory describes what was observed. The final reaction is never included.
\section{Controls}Development controls include outcome-only records, sham structured memory without a constitutive relation, and token-matched open-loop memory. These estimate outcome-summary, polished-structure, and token-volume effects. They are mechanism diagnostics and not part of the primary reserved comparison.
\section{Rendering robustness}All renderings share event identity, latent state, oracle reaction, rule ID, evidence groups, and split. Paraphrase consistency is the proportion of canonical contexts for which every rendering receives the correct reaction. Rendering-family performance and cross-render variance must be reported.
\section{Metrics}Primary metrics are five-class macro-F1 differences $B1-B0$ and $B1-M0$ on reserved canonical contexts, aggregated across renderings and clustered by canonical context. Supporting metrics include rule accuracy, grounded accuracy, citation validity, schema validity, paraphrase consistency, predecessor withholding, successor application, unsafe overreach, token use, latency, and invalid-response rate.
\section{Challenge gates}Before reserved calls, run current-only, assumption-only, memory-only, bag-of-words, identifier-only, structure-only, and event-count baselines on development. Explicit reaction phrases and hidden oracle-variable labels must be absent. Oracle replay, rendering equivalence, condition parity, and reference hashes must pass at 100\%.
\section{External API QA}Use the v0.4.2 response schema and deterministic interpreter. The v0.5 runner preserves raw responses, parsed and scored records, terminal statuses, model configuration, and call ordering. The run-completion validator requires every expected call to have exactly one terminal record and every completed call to have a score. Reserved execution is blocked until external API retry, restart, and structured-output QA pass.
\section{Release boundary}This package is suitable for generator development, baseline calibration, mock execution, and external development samples. It is not frozen for reserved evaluation. A release candidate must pass challenge baselines and external API QA, then issue new checksums without changing reserved states.
