All 1,440 calls returned HTTP 200 with finish_reason: stop and terminal status COMPLETED_VALID. Output ran to a median of 116 tokens and a maximum of 294 against the frozen 4,096 ceiling, so truncation was not merely rare, it was structurally impossible — against 4.0% on the sealed KIMI2 run.

Statelessness verified

Input tokens ranged from 1,504 to 2,049 across all 1,440 calls, tracking payload size and nothing else. There is no upward drift, so no context leaked between calls and each remained an independent decision. This is the same check that validated the KIMI2 reserved run.

2. Transport: 113 faults, nothing lost

The host is on Wi-Fi with no wired interface, and its radio power-saving was active during the run. That produced a burst of DNS resolution failures and TLS handshake timeouts, concentrated in the opening third and absent from the last 60%.

Pass one closed at 1,417/1,440 with pass: false. Because exhausted transport failures are recorded as restartable and never written to the call registry, relaunching the same command retried exactly those 23 and closed the run at 1,440/1,440 in about 100 seconds. Nothing was edited between passes.

This is the 13 August defect, repaired and now proven in production

The runner as originally supplied wrote failed calls to the registry as terminal, so a restart skipped them: a measured silent loss of 20%. The corrected runner has now met a genuinely degraded network and lost nothing. A representative trace:

CALL51-0000327 attempt 1 RETRYABLE_ERROR urlopen error [Errno -2] Name or service not known CALL51-0000327 attempt 2 RETRYABLE_ERROR urlopen error [Errno -2] Name or service not known CALL51-0000327 attempt 3 COMPLETED_VALID

The policy exercised its full depth rather than its happy path. Wi-Fi power saving has since been disabled on the host.

Declared: the host suspended for 70 minutes mid-run

The laptop entered sleep.target at 15:59:51 and left it at 17:09:24 — the lid-close default, since corrected. The run process was frozen for that interval and resumed without intervention.

It is disclosed because an auditor should know the host slept, but it did not corrupt the run: zero transport faults occur in the affected window, all 1,440 responses are valid, and input tokens stay flat across the boundary. Wall-clock timings from this run are therefore not a usable throughput measurement; per-call latency is (median 2.38 s, p95 4.63 s).

What is needed to open it

The delegated signature of 19 August released the Qwen3 development contrasts and states explicitly that it does not release the reserved split of any arm. Opening this run therefore requires a separate authorisation that does not yet exist.

Given that this is the single primary confirmatory claim of the programme, the recommendation is that it carry your own signature rather than a delegated one. Everything else is in place: the analysis is frozen and pre-registered, the estimator is the one that produced the sealed KIMI2 result, and its coverage characteristic was re-measured across a grid before this run was opened — confirming, not weakening, the published Finding 002.

Once authorised

The analysis is a single command and completes in seconds, with zero further model calls. The hierarchy is fixed: B1−B0 first, the key secondary tested only if the primary succeeds, M0−B0 exploratory; intention-to-evaluate denominator; memory-clustered bootstrap, 10,000 replicates, 95% percentile interval, seed 13082654.
