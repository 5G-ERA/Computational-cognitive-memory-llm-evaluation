Group A · six decisions

These change what the audit measures

A1Answered

Demote E4_INFLUENCE_UNEXPLAINED to INFO?

The release publishes no structured grounds field, so the only oracle-independent detector for this code is whether the free-text reason quotes an event identifier. Terra never does; Qwen3 usually does. It fires on 360/360 Terra cases and 54/360 Qwen3 cases.

A2Answered

Declare ΔIO an instrument-integrity endpoint rather than a discriminating one?

With A1 applied, deterministic Level 1 conformity is 97.5%–100% in every condition for both models. Structural, not incidental: the public response schema has four fields and the frozen runner already rejects schema-invalid responses, so nearly any response reaching the audit is Level 1 conformant. Same shape as the ceiling in the Terra decision arm.

Recommend

Keep ΔIO, state the ceiling explicitly, and report it as evidence that the retained artefacts support reconstruction in every condition — a claim the paper can make — rather than as a contrast expected to move.

Answer

YES

A4Answered

Level 2 as a release-integrity audit now, or extend the response schema and re-run?

§8.1 requires fields absent from the release to be marked NOT_RECORDED_IN_SOURCE_RELEASE and never inferred. §7.2 and §8.3 make several of those same fields mandatory components. Both readings are computed:

ReadingM0 L2 conformityB1 L2 conformityB1 criticalΔTrace
LITERAL0.00%0.00%100.00%+0.00 [+0.00, +0.00]
SCOPED100.00%74–75%25.00%−25 (the A3 artefact)
 Under LITERAL the estimand has a zero point and a zero-width interval in both models: it cannot move. Under SCOPED it is A3. Neither reading measures a system property.

The cause is structural, not editorial. The release has no trace-writing path. M0 and B1 objects are delivered to the model in the payload; the model returns only reaction, rule_id, decisive_event_ids and reason. Level 2 as specified audits the dataset, which the §14 checks confirm is invariant across all five contexts, all three renderings and both models, for every memory. That is also why the protocol reads as if written for Experiment 2, where the system writes a lifecycle trace κt and equation (36) compares it with a frozen reference certificate. Experiment 1 has no κt.

Recommend

Report Level 2 as a release-integrity audit for this paper — the retained artefacts are complete, coherent and non-rewritten, stated once for the release — and drop equation (7), declaring the schema extension as the §21 follow-on.

Answer

RELEASE-INTEGRITY NOW, EXTEND SCHEMA AS FOLLOW-ON

Group B · ten ratifications

Conventions the protocol leaves open

Each is a place where the protocol does not determine an implementation. I chose, and recorded the choice in the contracts. They need ratifying now: Adrian is writing the independent §17 validator from the contracts alone, and an unratified convention produces a disagreement that is about the specification rather than about either implementation.

B1
Rendering identifier (§3)
Not recorded on the call envelope. Derived from the context_id suffix: -STR → STRUCTURED, -CHR → CHRONOLOGICAL, -CON → CONCISE. Ratify the derivation into the frozen protocol?
Answer: RATIFY
B2
"Scientifically truncated" request (§6.1)
Implemented as: the payload carries every longitudinal record registered for the memory and every current record registered for the canonical context. Verified to hold for all 1800 expected calls.
Answer: RATIFY, RENAME PAYLOAD_REGISTRY_COMPLETE
B3
Decision boundary (§6.4)
The protocol names it but does not define it. Implemented as max(event_time) over the current records delivered in that payload.
Answer: RATIFY AS PAYLOAD EVIDENCE CUTOFF
B4
Self-declared grounds categories (§6.5)
The six categories cannot be read off a response that has no structured grounds field. Reduced to three deterministic obligations; the rest deferred to the human rubric rather than approximated by text heuristics.
Answer: RATIFY
B5
Current event as formation evidence (§6.6)
No oracle-free deterministic detector exists on this release — the claim lives in free text. Deferred to the frozen human rubric; raises nothing today.
Answer: HUMAN RUBRIC ONLY
B6
Prospective integrity hash (§7.3)
Equation (1) has five operands; three — attributed capability, evidence contract, verification window — are not recorded. Hash computed over the other three, and §8.2's non-rewrite test inherits the weakening. Ratify the degraded hash, or withdraw the non-rewrite test as unevaluable here?
Answer: REPORT AS PARTIAL FIELD STABILITY, WITHDRAW FULL NON-REWRITE CLAIM
B7
Competing evidence (§8.4)
The field exists but the release states no expectation of when it must be non-empty, so the check records NOT_EVALUABLE_FROM_SOURCE_RELEASE, exactly as §8.4 directs. Reference integrity is still checked.
Answer: NOT EVALUABLE FROM SOURCE RELEASE
B8
Human-detected codes (§16)
Four codes declared inert pending a frozen rubric, and E2_SCOPE_OVERREACH scored by its automated half only. So every conformity figure in results/ is deterministic-only and therefore an upper bound: the human layer can only lower it. Confirm the list, and that the paper carries the caveat?
Answer: RATIFY, DETERMINISTIC-ONLY UPPER BOUNDS
B9
Cluster coverage (§15)
8 development clusters. Our own coverage study puts 8-cluster bootstrap coverage near 89.6% against a nominal 95%, and 32-cluster near 92.5%. Confirm audit intervals carry the same disclosure the decision results already carry?
Answer: RATIFY
B10
Naming, against theory equation (36)
V4.7 defines audit conformity as the realised lifecycle trace matching an independently specified frozen reference certificate. This extension is oracle-independent and has no certificate, so it measures the rung below — functional auditability plus internal coherence — which is what §1 says it does. Rename to trace reconstructibility and trace coherence, reserving audit conformity for equation (36)?
Answer: USE RECONSTRUCTIBILITY AND COHERENCE, RESERVE AUDIT CONFORMITY FOR LIFECYCLE CERTIFICATE TEST
